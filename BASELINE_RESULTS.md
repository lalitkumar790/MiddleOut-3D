# First baseline run

**Status:** first prototype benchmark, not a claim of beating a production codec.

Run configuration: position quantization = **16 bits/axis**; median of **5 runs**; synthetic meshes generated by this project's fixture script. Environment reported by Python: Linux x86_64, Python 3.13.5, NumPy 2.3.5. Timing was collected in a container on an AMD EPYC 9V74 host; these numbers are not general hardware performance claims.

## How to interpret this

The **simple reference** and MO3D v1 both encode the same 16-bit quantized vertex positions and exact triangle index connectivity; both omit normals, UVs, colors, textures and materials. The main difference is face-index representation: the reference uses fixed-width 32-bit indices before zlib, while MO3D uses delta-encoded zigzag varints before zlib. This is a useful first ablation, although stream headers are not byte-identical.

MO3D was smaller than this narrow reference on some fixtures, but larger on others. This is a **mixed, preliminary result**, not a universal win. The generated fixtures are synthetic, and timing is from a virtualized environment.

The comparison against original OBJ file size is not a fair codec result: MO3D is lossy and contains only geometry/connectivity, while source formats can include formatting and more attributes. Gzip is included only as a lossless baseline on the exact source bytes.
